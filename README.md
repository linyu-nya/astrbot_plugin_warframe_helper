# Warframe Helper 插件

面向 AstrBot 的 Warframe（国际服）信息查询与交易助手。

本仓库由 [linyu-nya](https://github.com/linyu-nya/astrbot_plugin_warframe_helper) 独立维护，后续开发与插件更新使用本仓库的 `master` 分支。
基于 [moemoli 的原始项目](https://github.com/moemoli/astrbot_plugin_warframe_helper) 开发，保留原项目许可证与作者署名。

## 开发与打包

```bash
python -m pip install -r requirements.txt -r requirements-test.txt
python -m pytest -q
python scripts/package_plugin.py --theme release
```

打包脚本在仓库同级目录生成 ZIP，安装入口文件位于压缩包根目录。
虚拟环境、测试和开发文档不会进入安装包。

### 地区赏金查询

直接发送 `地球赏金`、`金星赏金`、`火卫二赏金`、`扎里曼赏金`、`圣所赏金`、`1999赏金`，也支持带 `/`。
无斜杠使用需要启用插件的无前缀命令配置。可在末尾附加平台，如 `/金星赏金 pc`。

- 地球：希图斯赏金、夜灵平原赏金。
- 金星：奥布山谷赏金、索拉里斯赏金。
- 火卫二：魔胎之境赏金；与解剖圣所分开查询。
- 扎里曼：老家赏金；接口提供时显示敌方派系。
- 圣所：解剖圣所赏金、科维兽赏金。
- 1999：六人组赏金。

`/赏金 地区或集团名` 查询指定集团，`/赏金` 查看当前接口提供的全部赏金。
新集团有任务数据时可直接按集团名称查询，无须把它归入旧平原。
显示任务名称、等级、阶段数值及剩余时间，不把阶段数值误称为掉落奖励。
官方仅公布种子的赏金优先从 [browse.wf 的公开轮换接口](https://browse.wf/live) 补全节点与额外目标，
按公开节点数据确认任务类型，再用游戏中文词典显示名称。轮换已过期、数据不完整或源站不可用时
不会推送未经确认的任务，查询会说明详情暂不可用。
普通平原赏金不自动推送。高效率赏金仅向已通过 `/推送开启` 注册的群发送文字通知：

- 扎里曼、圣所：先从该轮全部赏金确定最高等级，仅该等级的歼灭任务符合条件。
- 六人组：只选择明确标识为第 6 档的歼灭赏金，排除杀毒 Mod 奖励；不以列表位置猜测档位。
- 缺少有效到期时间、任务类型、等级或六人组档位依据时不推送。六人组只在公开轮换
  恰好有 7 档时按对应展示顺序取第 6 档，不使用官方种子猜任务内容。

插件网页配置中的“世界状态自动推送 → 高效率赏金推送”可独立关闭此类通知。
同一轮同一任务去重持久化；首次登记群只建立基线，后续轮换再推送。

### 周常与日历

- `沉沦之地` / `爬塔`：本周炼狱层数、任务类型、挑战及刷新倒计时。
- `1999日历` / `日历`：当前季节的日期、待办、奖励和覆写选项。
- `本周灵化` / `灵化`：当前普通轮回战甲与钢铁轮回灵化武器。

以上均支持 `/` 前缀和平台参数，沿用世界状态底图配置；不自动推送。
使用官方数据的生效/到期时间选择当前轮换，不取接口中预告的未来周。
日历的挑战名称和目标优先使用公开节点中文词典及要求数量，其余条目用已核对的中文称呼；
缺失译名时清理内部图标代码并保留可读原名，不猜造数值或奖励。
本周灵化不包含紫卡倾向和完整未来轮换表。

> 世界状态类指令支持平台参数（如 `pc / ps4 / xb1 / swi / cn`），例如：`/裂缝 cn`、`/突击 国服`。

国际服世界状态优先读取官方 CDN；官方响应不可用或结构无效时，自动回退到配置项 `warframestat_api_bases` 中的聚合接口。

裂缝默认按“古纪、前纪、中纪、后纪、安魂、全能”排列，同一纪元内按剩余时间升序排列。
如需恢复仅按剩余时间排序，可在插件配置中关闭“裂缝按纪元排序”。该配置同时作用于
图片回复和文字回退回复。

### 国服数据回退（参考 hole-wf-api 思路）

当 WeGame 直连接口出现 `-13/-16` 时，插件会按顺序尝试：

1. 签名 URL 直连
2. Playwright 浏览器抓取页面中的 `/ajax_get_worldState` 响应
3. 你配置的第三方备用 URL / Base URL（可对接自建 hole-wf-api）
4. 最后回退到国际服 PC worldstate，避免指令硬失败

以上回退链路已内置默认行为。

### 仲裁数据源（按 hole-wf-api 补齐）

`/仲裁` 现在采用多源策略：

1. 优先 `warframestat` 的 `/arbitration` JSON
2. 回退 `browse.wf/arbys.txt`（时间戳 + 节点）并自动映射节点名

### 群自动推送

- `/推送开启 [平台]`：AstrBot 管理员在当前群开启自动推送
- `/推送关闭`：关闭当前群自动推送
- `/推送状态`：查看当前群状态

自动推送使用纯文字，范围固定为：

- 钢铁之路、塞德娜、中断任务的全能裂缝，并显示剩余时间
- Lotus 的礼物和特殊活动，并显示剩余时间
- Warframe 官方更新新闻及网页链接
- 每日突击和每周执刑官，并显示剩余时间
- 奸商到访后的新库存，并显示离开前剩余时间

首次开启只记录当前内容作为基线，不会把已有内容集中补发。后续重启会读取持久化去重状态，
并补发停机期间出现且当前仍能从接口获取的新内容。科研、双衍王境和入侵仅提供查询，不自动推送。

轮询间隔可在插件配置的“世界状态自动推送”中设置，默认 60 秒，最小 30 秒。

### 百科查询（灰机 Wiki）

- `/wk <关键词>`：查询 Warframe 灰机 Wiki
- `/翻译 <关键词>` 或 `翻译 <关键词>`：使用本地别名表查询对应英文规范名，英文规范名可反查已有中文别名。例如 `翻译 夜灵p` 返回 `Revenant Prime`。
- 查询会先使用本地别名映射；命中后打开对应的 Wiki 精确页面，否则返回 Wiki 搜索页
- Wiki 查询不依赖 `warframe.market` 校验，因此也可以映射非交易词条

当 Wiki API 精确命中时返回词条页；未找到词条或 API 不可用时都会降级到搜索页，并区分“未找到”和“暂时无法确认”两种情况。

### 知识增强聊天（RAG）

先在 AstrBot 的“模型提供商”配置可用的 Embedding，并在“知识库”中新建名为 `Warframe` 的知识库；名称也可在插件网页配置的“Warframe 知识增强聊天（RAG）”中修改。建议使用 AstrBot 4.28.2 或更新版本。管理员随后执行 `/wf知识 初始化`，导入六条有官方中文来源的示例问答；重复执行不会覆盖已修改的同名问题。也支持在 AstrBot 知识库网页上传文档，文档中可填写单独一行 `来源：https://...` 作为原始来源。

群聊直接 `@bot 初始战甲选错了怎么办？`，私聊直接提问，无须额外关键词。插件在 AstrBot 请求模型前语义检索候选资料并注入本轮临时上下文，保留原有人格、聊天记录和工具。普通聊天同样可触发检索，但模型应忽略无关资料；没有内容、检索失败或超时时继续正常聊天，也允许模型使用自身知识或已配置的网页搜索。检索结果不要求与管理员问句完全一致。只有模型使用 `[[WFKB:编号]]` 引用候选资料时，回复才附“知识库参考”与实际文档来源，避免把普通聊天或网页搜索内容误标为知识库知识。

推荐关闭 AstrBot 的知识库 agentic 模式，并在 AI 配置的知识库列表中留空，让插件控制一次检索及超时。知识库本身仍在 AstrBot 网页管理。若该配置已经选择原生自动知识库，插件会复用 AstrBot 已注入的候选内容；原生检索为空时不会重试，避免重复 Embedding。会话级明确关闭知识库时同样尊重该设置。关闭本插件开关仅关闭插件增强，原生知识库是否启用仍由 AstrBot 配置决定。

默认最多等待插件检索 5 秒，最多注入 3 个片段、6000 字符，可在插件网页配置调整。日志以 `[WFKnowledgeRAG]` 开头，记录 `outcome`、片段数和 `elapsed_ms`；`injected/empty/error/timeout` 对应插件检索结果，`native_reused/native_empty` 对应复用原生结果。复用路径的耗时只统计钩子处理，原生 Embedding 请求耗时需看 AstrBot 自身日志。引用标记能否生成取决于聊天模型遵循提示词的能力；真实 QQ/模型效果需要安装后验证。

来源尾注当前针对完整文本回复；使用原生流式输出的平台可能先输出引用标记，建议首轮测试关闭流式输出。修改插件的知识库名称后请重载插件。

- `/wf知识 问题 | 答案 | 来源链接`：管理员新增或覆盖问答；来源链接可省略。
- `/wf知识 收录 标题 | 正文 | 来源链接`：管理员收录主题资料；不需要预制问题。正文支持换行，最多 16000 字符，文档由 AstrBot 分块并建立向量索引。
- `/wf知识 查看 问题`、`/wf知识 删除 问题`、`/wf知识 列表`：管理员查看、删除和列出问答。
- `/wf知识 查看 标题`、`/wf知识 删除 标题`：同样适用于主题资料。
- `/wf知识 资料包`：导入 40 篇独立整理的官方来源主题资料，正文包含机制、操作与误区。重复执行跳过已有同版内容；从旧资料包升级时更新插件托管的同标题条目，不覆盖管理员手工编辑过的条目。提供商中途失败时保留已完成进度，修复后可重新执行继续。
- `/wf知识 导入`：从插件数据目录的 `astrbot_plugin_warframe_helper/knowledge_import/` 导入 UTF-8 `.md` 或 `.txt` 文件，一次最多 50 个，每个最多 256 KiB。首行 `# 标题` 可指定标题，末尾支持 `来源：URL`、`核验日期：YYYY-MM-DD`、`适用范围：文字`；元数据不作为正文重复保存。
- `/wf知识 状态`：显示知识库、索引数量、Embedding ID/模型/维度、提供商 `input_type` 配置，以及本会话最近的 RAG 状态、候选片段和引用数。诊断不生成问题向量；显示的配置值不证明提供商正确区分 `query/passage`。
- `/wf知识 测试 问题`：管理员直接测试混合检索，不调用聊天模型，显示候选标题、来源和耗时。候选出现不等于模型会使用它，也不证明向量路径成功（AstrBot 可能使用 BM25 回退）。
- `/wf知识 评测`：运行 40 道主题改写问题和 5 道闲聊题，需要最多 45 次知识库检索，建议私聊使用。报告候选召回、错误、P50/P95，完整报告保存在插件数据目录 `knowledge_evaluation_last.json`。闲聊有候选单独统计，不能据此推断模型误答或引用。
- 开启插件的“无前缀指令触发”后，管理命令也可直接发送 `wf知识 ...`。

问答原文和 AstrBot 文档 ID 备份在 AstrBot 插件数据目录下的 `astrbot_plugin_warframe_helper/knowledge_entries.json`。修改或删除会同步更新 AstrBot 知识库；不要直接删除这个备份文件。官方中文示例只做简短事实说明与来源回链，不包含灰机 Wiki 正文。

主题资料包依据官方中英文指南作中文事实整理，覆盖战甲选择、星图、Mod、精通段位、集团、开放世界、遗物和伤害/异常状态的基本区别。核验日期记录来源网页检查日期，并非全项实机复测；伤害状态条目只提供概念，未声称当前热修的具体增伤上限。原有六条问答可继续保留，主要资料建议使用主题正文。

诊断统计只保留最近 128 个会话和 200 个插件直接检索耗时样本，重载会清空。P50/P95 不包含原生结果的解析耗时；`native_reused` 显示的 `0 ms` 不是 Embedding 的网络耗时。实际召回率和模型引用效果需要在已配置提供商的 AstrBot 上运行测试。

开发时可用 `python scripts/export_knowledge_pack.py --output ../warframe-knowledge-topics.zip` 导出 40 个 Markdown 文件，供 AstrBot 网页上传或放入上述导入目录；压缩包中的 `manifest.json` 记录原始来源和核验信息。

资料正文才是实际参与分块与 Embedding 的知识，来源链接不会自动下载网页。每篇文档按机制、操作及误区分节；覆盖新手进度、Mod、遗物、交易、集团、专精、机甲、赏金和 1999 日历。任务轮换、掉落表和市场价格需要实时查询；历史数值规则明确标注，核验日期不代表当日全内容实机测试。

升级到 v0.6.5 后，管理员重新执行 `/wf知识 资料包` 即可更新之前由同一命令导入的 25 篇资料并增加 15 篇。升级插件本身不会自动重建已部署知识库。如果旧文档是手动在 AstrBot 网页上传的，请仅替换旧资料包的相应文档并重新索引，再上传新包中的 `.md`，不要把 `manifest.json` 当知识文档；保留自己收录的其他资料，避免旧摘要与新正文重复召回。

## 自定义图片底图

插件配置菜单中的“自定义渲染底图”可以为图片回复设置本地图片或 HTTP(S) 图片 URL。
该功能默认关闭，不会改变现有模板；本版本不提供文件上传按钮。

底图按以下顺序选择：

1. 裂缝、价格或世界状态分类底图
2. 全局默认底图
3. 当前 HTML 模板的原始背景

分类范围如下：

- 裂缝：普通裂缝、钢铁裂缝、九重天裂缝
- 价格：`/wm`、`/wmr`、`/wfp`
- 世界状态：周期、活动、赏金及通用世界状态卡
- 其他图片回复：仅使用全局默认底图

### 底图来源

支持 PNG、JPEG 和 WebP，单张最大 15 MiB，解码后最大 4000 万像素。远程图片会在
插件启动时下载并保存到内存，查询时不会重复请求。修改配置后需要保存并重载插件。

输出图片默认使用无损 WebP，保留截图的原始像素并显著降低底图型长图的文件大小。
若转换失败或 WebP 未小于原 PNG，将自动保留 PNG。需要强制兼容 PNG 时，把插件
配置的 `render_image_format` 改为 `png`；此设置需要重载插件。

```text
# Windows 绝对路径
D:\Pictures\warframe-background.webp

# Docker 容器内路径，必须确保宿主机目录已挂载到容器
/AstrBot/data/warframe/background.png

# 相对于插件目录
assets/background/custom.jpg

# 远程图片
https://example.com/warframe/background.webp
```

Docker 部署填写的是容器内路径，不是宿主机路径。例如将宿主机目录挂载为
`/AstrBot/data/warframe` 后，再填写该容器路径下的图片。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 启用自定义底图 | 关闭 | 总开关；关闭时不读取或下载底图 |
| 全局/裂缝/价格/世界状态底图 | 空 | 分类为空或失败时回退全局底图 |
| 底图填充方式 | `cover` | 支持 `cover`、`contain`、`width`、`repeat-y` |
| 底图位置 | `center center` | 例如 `center top`、`50% 20%` |
| 启用底图遮罩 | 开启 | 可独立关闭 |
| 遮罩颜色/不透明度 | `#0f172a` / `42` | 不透明度范围 0-100 |
| 面板颜色/不透明度 | `#0f172a` / `58` | 不透明度越低，透出的底图越多 |
| 启用毛玻璃效果 | 开启 | 可独立关闭，不影响底图与透明面板 |
| 毛玻璃模糊程度 | `6px` | 范围 0-30px |
| 文字明暗模式 | `light` | 深色底图用 `light`，浅色底图可用 `dark` |

填充方式不会改变图片宽高比：`cover` 铺满并允许裁切，`contain` 完整显示但可能留白，
`width` 按画布宽度显示一次，`repeat-y` 按宽度纵向重复，适合超长列表或无缝纹理。

如果路径不存在、下载失败、格式不支持或图片超限，插件会记录 warning，并自动回退到
上一级底图或原模板背景，不会让查询指令失败。

## Playwright 浏览器安装

插件使用 Playwright 进行截图渲染。首次部署请先安装浏览器依赖与浏览器内核：

```bash
playwright install-deps
playwright install
```

若只需要 Chromium，也可以指定：

```bash
playwright install-deps chromium
playwright install chromium
```

> 说明：在 Windows/macOS 上，`playwright install-deps` 可能提示不支持，可忽略；`playwright install` 仍需执行。
