# 灰机 Wiki 统一查询设计

## 目标

将现有资料查询统一为 `/wk <关键词>`，回复灰机 Warframe Wiki 的词条链接或搜索页链接。`wk` 不再作为紫卡查询别名；紫卡查询只保留 `/wmr` 与 `/wr`。旧命令及全部别名 `/武器`、`/weapon`、`/wfweapon`、`/战甲`、`/warframe`、`/frame`、`/wfwarframe`、`/MOD`、`/mod`、`/模组`、`/mods`、`/掉落`、`/drop`、`/drops`、`/遗物`、`/relic`、`/relics` 全部移除，包括 AstrBot 带前缀命令注册与插件无前缀路由。

## 命令行为

- `/wk <关键词>` 和无前缀形式 `wk <关键词>` 执行 Wiki 查询。
- 空关键词返回用法提示：`用法：/wk <关键词>`。
- `/wfmap <别名> <全称>` 仅允许 AstrBot 管理员新增或覆盖自定义映射。第一个非空白参数是别名，后续全部文本作为允许包含空格的全称；参数不足时返回用法，不再执行市场物品查询或校验。
- `/wfmapdel <别名>` 仅允许 AstrBot 管理员删除自定义映射。它不要求重复填写全称，也不删除插件内置映射；删除自定义覆盖后若同名内置映射重新生效，回复中明确提示恢复后的内置目标。
- `/wfmapq <全称>` 允许所有用户按完整名称反查全部别名。全称比较忽略大小写、首尾空白及连续空白差异，结果区分内置别名与自定义别名；没有别名时返回明确的未找到提示。
- 上述三个命令均支持插件已有的无前缀命令路由；帮助页展示该命令族。
- 现有 `/简称补充` 暂时作为管理员兼容入口保留，但与 `/wfmap` 写入同一个自定义映射分区，不再修改插件内置映射文件，也不在主要帮助中重复展示。
- `wk` 使用同一份简称/外号映射数据完成关键词重定向，不执行市场商品校验。
- 精确命中时返回：`以下是“原关键词”的 Wiki 页面：`，下一行附最终词条 URL。
- 未命中时返回：`没有查到“原关键词”，以下是 Wiki 搜索页：`，下一行附搜索 URL。
- API 不可用或响应无法验证时返回：`暂时无法确认“原关键词”是否有精确词条，以下是 Wiki 搜索页：`，下一行附搜索 URL。此状态不能复用“没有查到”文案。
- Wiki 回复使用纯文本，保证 QQ 中的链接可以点击或复制。

## 查询流程

1. 对用户关键词做去首尾空白处理；空内容直接返回用法。
2. 从映射命令共用的三个分区解析规范名称：基础别名、紫卡武器别名、用户别名。合并顺序保持现状，后者覆盖前者，即用户别名 > 紫卡武器别名 > 基础别名。匹配规则保持现有行为：先精确匹配，否则选择最长前缀；Wiki 查询不依赖物品必须可交易，因此映射层需要提供只解析别名、不要求命中 warframe.market 商品的公开方法。例如“照相机 -> 奥克绪罗斯/Oxylus”即使无法通过 warframe.market 商品校验，仍可作为 Wiki 查询关键词。
3. 请求灰机标准 MediaWiki Action API：

   `https://warframe.huijiwiki.com/api.php?action=query&prop=info&inprop=url&titles=<关键词>&redirects=1&format=json&formatversion=2`

4. `query.pages` 中存在有效页面时，使用页面对象的 `fullurl`。`redirects=1` 让 MediaWiki 解析重定向，避免自行猜测最终标题和 URL 编码。
5. 页面带有 `missing` 或 `invalid` 时视为未命中。
6. API 超时、403、Cloudflare 验证页、非 JSON 或结构异常时，不把请求抛给用户，也不声称精确命中或不存在，而是以“无法确认”状态降级到搜索页。

## URL 生成

搜索页固定使用灰机当前可用的 MediaWiki 搜索入口，并通过标准查询参数编码：

`https://warframe.huijiwiki.com/index.php?title=特殊:搜索&profile=default&search=<规范关键词>&sort=just_match`

由 `urllib.parse.urlencode` 负责中文和特殊字符编码，禁止手工拼接百分号编码。精确命中的页面 URL 优先采用 API 返回的 `fullurl`；若响应确认页面存在但缺少 `fullurl`，才使用 URL 编码后的标题构造 `/wiki/<标题>`。

验收示例：搜索“电男 Prime +&?#%”时，`search` 参数解码后必须与原规范关键词完全一致，`+`、`&`、`?`、`#`、`%` 不得改变参数边界；空格可编码为 `+`。MediaWiki 的 `titles` 会把 `|` 解释为多标题分隔符，因此关键词包含 `|` 时跳过精确 API 查询，直接返回“无法确认”搜索页；搜索 URL 中的 `|` 必须编码为 `%7C`。精确查询每次只接受一个页面，若响应包含多个页面，也视为无法验证并降级。

## 组件边界

- `clients/huiji_wiki_client.py`：封装灰机 API 请求、响应解析、页面 URL 与搜索 URL 生成，返回“命中、缺页、不可用”三态结果。网络异常转换为明确的“不可用”结果。
- `services/wiki_commands.py`：解析命令参数、调用别名重定向与 Wiki 客户端、生成最终纯文本。
- `mappers/nickname_registry.py`：提供新增、删除与按全称反查自定义映射的持久化操作；删除只能作用于用户别名分区。
- `mappers/term_mapping.py`：新增公开的别名规范化、写入、删除与反查方法，不触发商品缓存初始化，也不要求规范名称能匹配可交易商品。写入或删除成功后立即重载内存别名索引，使后续 `wk` 无需重启即可生效。
- `services/mapping_commands.py`：封装 `/wfmap`、`/wfmapdel`、`/wfmapq` 的参数解析、权限无关业务结果和回复文案，避免继续扩张 `main.py`。
- `main.py`：注册 Wiki 与映射命令，从紫卡别名中移除 `wk`，删除旧资料命令注册与实现，更新无前缀路由和帮助卡片。
- `services/market/wmr.py`、`README.md`：移除将 `wk` 描述为紫卡别名的文案，更新命令说明。

## 错误处理

- 灰机当前可能返回 Cloudflare 挑战页，即使状态码或请求本身可达，也必须先验证 `Content-Type` 与 JSON 结构。
- API 不可用时仍返回搜索页，因此 `wk` 在网络受限环境中保持可用。
- 别名未命中不是错误，直接使用用户原关键词查询。
- 别名命中但目标不是可交易商品也不是错误；这类目标仍可在 Wiki 中存在，不能被 warframe.market 缓存否决。
- 别名命中但 Wiki 没有对应精确词条时，搜索页使用重定向后的规范关键词，以提高搜索质量；回复中的引号仍展示用户原关键词。
- 非管理员调用 `/wfmap` 或 `/wfmapdel` 时拒绝修改并保留现有数据；`/wfmapq` 不需要管理员权限。
- 自定义别名覆盖同名内置别名；删除自定义项后自然回退到内置项。尝试删除仅存在于内置分区的别名时拒绝并提示“内置映射不可删除”。
- 映射写入插件数据目录中的用户别名分区，不修改随插件发布的默认映射文件，保证插件升级后仍然保留。

## 测试

- Wiki 客户端：精确命中、重定向命中、缺页、403、超时、HTML 挑战页、URL 编码。
- 别名解析：基础别名、紫卡武器别名和用户别名的覆盖顺序，精确匹配与最长前缀匹配，未知词保持原样，映射不初始化或依赖市场商品缓存。
- 映射管理：管理员新增和覆盖、非管理员拒绝、包含空格的全称、立即生效、数据文件持久化、兼容入口写入同一分区。
- 映射删除：删除自定义项、删除覆盖后恢复内置项、拒绝删除纯内置项、非管理员拒绝、删除不存在项。
- 映射反查：按全称忽略大小写和空白差异，返回所有基础/紫卡武器/用户别名并标明来源，不接受别名替代全称查询。
- 不可交易别名回归：管理员执行 `/wfmap 照相机 奥克绪罗斯` 后，`/wfmapq 奥克绪罗斯` 返回“照相机”，`wk 照相机` 使用“奥克绪罗斯”查询 Wiki，全流程不得初始化或校验市场商品缓存。
- 命令服务：空参数、精确页面回复、确认缺页的搜索回复、API 不可用的“无法确认”回复。
- URL 编码：覆盖中文、空格、`+`、`&`、`?`、`#`、`%`、`|`；包含 `|` 时不得发起多标题精确查询。
- 可靠降级：覆盖 DNS、连接、TLS、超时、429、其他 4xx、5xx、HTTP 200 的 API `error`、HTML 挑战页、非 JSON、空 `pages`、多个页面、页面缺少必要字段；均不得向上抛异常，且必须返回编码正确的搜索链接。
- 命令接线：`wk` 指向 Wiki；`wmr`/`wr` 指向紫卡；旧资料命令和别名不再注册；帮助文本不再展示旧命令。
- 完成后运行全量测试，确认市场、世界状态、无前缀路由和图片渲染不受影响。

## 文档依据

- 灰机官方说明其生产可用 API endpoint 为 `/api.php`，并兼容 MediaWiki 标准 `/w/api.php`。
- MediaWiki `prop=info&inprop=url` 提供页面 `fullurl`；`redirects=1` 解析重定向。
- MediaWiki `action=opensearch` 适合标题联想，但不能可靠表达“用户关键词恰好命中”，因此本功能不使用它作为精确命中判定。
