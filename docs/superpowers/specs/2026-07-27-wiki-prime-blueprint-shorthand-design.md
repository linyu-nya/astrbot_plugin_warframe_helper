# Wiki 查询后缀简写设计

## 目标

让 Wiki 查询和别名重定向在命中已知物品或别名后，自动识别以下系统级后缀：

- `p` 或 `P` 等同于 `Prime`
- `总图` 等同于 `蓝图`

管理员无需为每个物品重复添加 `物品p`、`物品p总图` 等组合映射。

## 解析规则

1. 首先按照现有最长前缀规则匹配内置别名或用户别名。
2. 仅当基础别名匹配成功时，解析其后的后缀。
3. 后缀中的独立 `p` 或紧随基础别名的 `p` 规范化为 `Prime`。
4. 后缀中的 `总图` 规范化为 `蓝图`。
5. 其他后缀继续保留并使用现有空格及 `Prime` 大小写规范化。

示例：

| 输入 | 解析结果 |
| --- | --- |
| `圣英` | `afentis` |
| `圣英p` | `afentis Prime` |
| `圣英P总图` | `afentis Prime 蓝图` |
| `咖喱p总图` | `Excalibur Prime 蓝图` |

## 安全边界

- 不对未匹配的任意英文单词展开末尾 `p`，避免把 `Amp` 误解析为 `Am Prime`。
- 用户自定义精确映射保持最高优先级，管理员仍可显式覆盖系统行为。
- 既有错误用户映射不会被自动删除；升级后可通过 `/wfmapdel 别名` 删除一次，使系统规则接管。

## 实现位置

- 在别名解析层增加后缀规范化，不向昵称 JSON 批量写入组合数据。
- `wk`、市场查询及其他复用别名解析器的功能共享同一规则。
- 不修改灰机 Wiki 客户端的词条存在性判断或 URL 安全校验。

## 验证

- 覆盖 `p`、`P`、`Prime` 与 `总图`、`蓝图` 的组合。
- 验证基础物品和 Prime 物品保持为不同规范名称。
- 验证未知名称和 `Amp` 等末尾含 `p` 的名称不被改写。
- 运行完整测试集、编译检查和 `git diff --check`。
